# Sushi Syndicate — статус и роадмап

Живой рабочий журнал проекта. Подробности архитектуры — в `ARCHITECTURE.md`.

## ⏱️ Ворклог
- Сумарно витрачено на сайт: **~30 годин** (станом на 2026-06-14).

## ✅ Сделано
- **Фронтенд** (Next.js 15, App Router, TS): витрина, корзина (Context+localStorage), чекаут, адаптив, Hero-слайдер акций, мобильный UX.
- **Реальная Google-аутентификация** (Supabase Auth):
  - `/admin/login` → OAuth, `/auth/callback`, `middleware` гардит `/admin`.
  - Роль из таблицы `profiles` (заполняется триггером из `allowed_staff`); экран «Немає доступу» для не-белого списка.
  - Белый список сотрудников — CRUD в БД (`/admin/staff`).
- **Весь каталог на Supabase** (хардкод убран):
  - Публичный сайт читает из БД через SSR (`page.tsx` → `publicData.server` → `PublicDataProvider`), `force-dynamic`.
  - Админ-слой данных `src/features/admin/db.ts` (хуки `useDb*` + мутации) — товары, категории, **подкатегории** (новая сущность + страница), ингредиенты (КБЖУ), акции, промокоды, история цен.
  - **Soft-delete товаров** (корзина 90 дней, авто-очистка).
  - **Граммовка ингредиентов** → авто-расчёт веса и КБЖУ порции (форма товара + карточка на сайте).
  - **Bulk-цены** по ингредиенту и **история цен** с откатом (`price_history` в БД).
- **Заказы и отзывы пишутся в БД** (`orders`/`order_items`/`reviews`) + Telegram.
  - Заказ: цены и скидка по промокоду **пересчитываются на сервере из БД** (защита от подмены цен на клиенте).
- **Админ-просмотр заказов** (`/admin/orders`): список с позициями, смена статуса (нове/підтверджено/виконано/скасовано), фильтр.
- **Модерация отзывов** (`/admin/reviews`): схвалити/відхилити/видалити, фильтры.
- **Доставка по адресу**: автоподсказки (Photon/OSM, без ключа) → координаты → расчёт цены (Haversine ×1.3 × тариф), пересчёт на сервере, запись в `orders.delivery_cost`. Тариф редактируется в `/admin/settings` (origin, базовая цена/км, шаг, бесплатно-от, макс.км). Настройки в `settings` (key `delivery`).
- **Rate-limit** на `/api/order` (6/мин) и `/api/review` (4/мин) по IP (in-memory, `src/lib/rateLimit.ts`).
- **Спец-пункты навигации** «Новинки»/«Акції» — тумблер видимости в `/admin/categories` (сущность не удаляется), хранится в `settings` (key `nav_specials`).
- **Bulk-цены** — теперь по ингредиенту / категории / подкатегории.
- **Редактирование категорий и подкатегорий** (модалки).
- **Схема БД** (миграции в `supabase/migrations/`): init + subcategories, products.subcategory_id, soft-delete, КБЖУ, граммовка, price_history, сид каталога.
- **Деплой**: прод `syndicatesushi.vercel.app`, git-автодеплой Vercel↔GitHub **работает** (push в main → авто-деплой).

## 🔐 Security-аудит и хардинг (2026-06-16)
Полный аудит (безопасность / производительность / качество). **Спринт 1 (критичное) — сделано:**
- ✅ **Доступ к `/admin`** проверяется на сервере по роли из `profiles` (middleware), а не только на клиенте — чужой Google-аккаунт получает отказ.
- ✅ **Отзывы**: закрыт публичный insert (миграция `..._reviews_insert_lockdown`, применена к проду).
- ✅ **Промо-цена** заказа берётся авторитетно с сервера (`promos.promo_price` + проверка дат) — нет рассинхрона «акция на клиенте / полная цена в заказе».
- ✅ **Промокод**: экранирование LIKE — `%` больше не матчит случайный код.
- ✅ **Потеря заказа**: при сбое БД+Telegram → честная `502`, корзина не очищается.
- ✅ **Не-молчаливые мутации**: sync ингредиентов/сетов и `dbUpdatePrice` возвращают ошибку; массовая правка цен не рассинхронит историю.
- 🔜 **Спринт 2 (план)**: фото товаров → Supabase Storage + `next/image`; ISR главной вместо `force-dynamic`; лимиты длины/размера payload в API; чистка мёртвых полей `desc/fullDesc`.
- 🔜 **Спринт 3 (тех-долг)**: распределённый rate-limit (Redis); белый список ключей для публичного чтения `settings`; единый `slugify`/`mapProduct`.

## ✨ Сессия 2026-06-17 (баннеры, акции, R2, доставка)
- **Cloudflare R2** подключён как хранилище картинок (S3-совместимый, `@aws-sdk/client-s3` + `sharp`): загрузка через API → конвертация в **WebP** → R2, в БД хранится URL. Хелперы `src/lib/r2.ts`, `src/lib/imageUpload.ts`, `src/lib/adminAuth.ts`. Бакет `syndicatesushi`, публичный `R2_PUBLIC_URL`.
- **Баннеры Hero — отдельная сущность** (таблица `banners`, миграция `20260617120000_banners.sql` применена к проду). Клиент сам рисует готовый баннер-картинку и грузит в `/admin/promos` → вкладка **«Баннери»** (загрузка/превью/вкл-выкл/удаление/порядок drag&drop). `HeroPromoSlider` теперь крутит баннеры-картинки (без клика/цены). API `/api/banners` (POST/DELETE).
- **Фото товаров → R2** (роадмап №1): загрузка в `/admin/products` идёт через `/api/upload` (WebP+R2), не data URL. Существующие data-URL фото **мигрированы** в R2 (0 осталось). SSR-payload главной стал легче.
- **Акции переосмыслены** (роадмап №15): убраны мёртвые поля `title`/`label`/`bannerImagePath` из формы/таблицы; акция = товар + акционная цена + даты «Діє з/до» + «Активна». **Скидка видна на сайте**: эффективная цена считается в `publicData.server` (активная акция в пределах дат и ниже каталожной) → `Product.price`/`oldPrice`; карточка/модалка/корзина показывают акционную цену + зачёркнутую старую. «Стара ціна» в форме read-only (из цены товара). Поле «Товар» — кастомный `AdminSelect` (поиск, портал, не обрезается).
- **Секция Hero-слайдера на главной** → три вкладки **«Новинки» (НОВЕ) / «Хіти» (ХІТ) / «Акції» (со скидкой)**, у каждой свой слайдер; вкладки в стиле кнопок «Фільтри/Сортування».
- **Промокод в чекауте** — кнопка «Застосувати» внутри инпута: проверка через `/api/promo/check` (service-role), пересчёт суммы (строка «Знижка») или «неактуальний».
- **Доставка — авторасчёт убран полностью**: вместо Photon-подсказок/координат/Haversine — одно поле «Адреса доставки» + подпись «від 100 грн, далі залежно від відстані». `/api/order` больше не считает `delivery_cost` (=0), адрес идёт в Telegram/админку — менеджер прорахує вручну.
- **Доска заказов** (`/admin/orders/board`): убрана локальная «Оновити» (осталась глобальная), добавлен **фильтр по дате** с дефолтом «сегодня».

## ⚠️ Не забыть
- **Не запускать `supabase db push`**: схему применяли напрямую (SQL), таблица миграций рассинхронизирована — упадёт без `migration repair`. Изменения БД делать напрямую/через SQL Editor.
- Прямое подключение `db.<ref>.supabase.co` не резолвится локально (IPv6) — использовать **session pooler** (`aws-1-eu-central-1.pooler.supabase.com`), пароль из `SUPABASE_DB_PASSWORD` (в URL он URL-энкодирован).
- Бот-токен в `.env.local` мог быть засвечен — заменить через `/revoke` @BotFather (решено оставить как есть).
- ✅ `client_secret_*.json` удалён из корня (был gitignored, приложению не нужен).
- **`sharp` на Vercel**: нативная libvips грузится через `dlopen`, file-tracer Next её не видит → API с `sharp` (`/api/upload`, `/api/banners`) падали 500 (`ERR_DLOPEN_FAILED: libvips-cpp.so`). Решено в `next.config.mjs`: `outputFileTracingIncludes` для `@img/**` + `serverExternalPackages` + ленивый `import("sharp")`. При добавлении новых роутов с sharp — дописать их в `outputFileTracingIncludes`.
- **R2-переменные (`R2_*`, 5 шт) обязательны в Vercel Production** — без них загрузка фото/баннеров не работает (показ уже загруженных — работает, R2 публичный).
